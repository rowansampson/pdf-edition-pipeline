# PDF Edition Pipeline

> The Python pipeline behind The People's Register's downloadable editions. Every issue publishes online and as a revisioned PDF, generated by one script.

![CI](https://github.com/rowansampson/pdf-edition-pipeline/actions/workflows/build-sample.yml/badge.svg) ![Python 3.12+](https://img.shields.io/badge/python-3.12%2B-2f7d54) ![License](https://img.shields.io/badge/license-MIT-b8860b)

---

## Run the sample

```bash
pip install reportlab
python3 sample/build_journal_pdf.py --issue "Vol. 01" --output journal.pdf
```

The sample is fully self-contained: the journal's content model (masthead, issue metadata, six cluster chapters with wards and field-report focus), brand typography, and table composition — distilled into readable code.

## What the production pipeline adds

- Per-issue content models (editorial, cluster chapters, photo desk, consolidated metrics)
- Versioned release outputs (`journal.pdf?v=2`)
- Secure asset embedding for field photography
- Release triggers for the Brevo issue-alert sequence

## Design decisions

1. **One script, one output.** No build farm for a document a single operator ships; the pipeline stays as boring as the stack.
2. **Content is data.** Issues are declared as dictionaries; a new edition is a data entry, not a code change.
3. **Brand tokens travel.** Colours, type and spacing come from the same token layer as the web platform.
